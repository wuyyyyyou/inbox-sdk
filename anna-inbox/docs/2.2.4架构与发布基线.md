# Anna Inbox 2.2.4 架构与发布基线

## 产品基线

2.0 的主界面是三栏工作台：左侧 AI 侧栏，中间 Inbox Workspace，右侧账户栏。点击邮件后，Mail Detail 从工作区右侧展开。

**唯一智能入口**为 Anna AI Sidebar（`start_ai_turn`）：自然语言搜索、总结、写改稿、整理建议。Brief 产品面下线，不再主路径执行 Phase1/Phase2 Attention Card 扫描。整理、发送、删除和标签 mutation 均须明确用户操作确认。

## 当前版本（App 2.1.4 / Tool 2.2.4）

### Host Agent Session 与白名单工具

- AI 侧栏主路径使用 `anna.agent.session`，由 Host Agent 在官方 `systemPrompt` 和显式白名单中选型。
- 前端新增流式会话适配层，支持文本增量、工具结果、Host run 取消、会话复用与清理。
- Executa 新增 `ai_*` 细粒度工具及本地缓存查询；搜索按 mailbox + conversation_id 限额，正文读取与索引检索分离。
- 发送、删除、标签变更和整理确认不进入 Agent 自动工具环，仍由用户操作触发。

### AI 侧栏统一与 Brief 下线

- 前端初始化不再依赖 Brief 扫描首屏；启动时清理旧 Brief 扫描存储。
- 后端删除 `brief_flow` / `phase1` 主路径；`pipeline` 仅保留 custom scan；describe/dispatcher 移除 `start/continue_mail_agent_run`。
- 能力并入侧栏：问答/搜索走 Agent 白名单工具与 Ask；整理走 `organize`（Needs reply + Can clean up 确认批处理）。
- Ask history 保留 7 天；每条会话独立 `conversationId`。

### Ask 搜索与回答

- 默认 `live_search_metadata_and_cache`；正文仅 top-N / 显式全文时回源。
- 宽查询优先本地缓存；需回复类本地噪声降权。
- 条数解析、预算分配与截断 JSON 失败语义保持收紧（不伪装成功）。

### 邮件详情与附件预览

- 详情滚动仅作用于 `.mail-detail-context`，避免带动外层 / 浏览器滚动条。
- 自动同步与 soft prune 保留当前打开邮件；同线程刷新不清附件预览、不误关详情抽屉。

### 继承能力

- 回复/转发/Compose 富文本（`body_html` + 后端白名单净化）。
- AI Agent Session 流式会话、工具结果解析、取消/恢复；详情/兼容路径保留 AI Router 澄清弹层与 `start_ai_turn` 短 wait 建 run。
- Sampling grant 预算快照；多邮箱切换与 History 静默同步。
- 外发多附件 stage、Cc/Bcc、发送前可撤销；平台安全 trace 诊断。

## 代码边界

- `mail_agent/ai_turn/`、`anna_inbox_executa/ai_turn_flow.py`：侧栏路由与执行。
- `mail_agent/ask/`：Ask 规划、搜索、回答与预算。
- `features/home/HomeView.tsx`、`features/mail-detail/MailDetailDrawer.tsx`：工作台、详情、附件预览。
- `app/useAppController.ts`、`app/state.ts`：状态、静默同步、详情打开保护。
- `mail_agent/mail_providers/gmail/`：Gmail API、缓存、外发 HTML。

2. `cd anna-inbox && npm test && npm run build`
3. 相关 Python 脚本式测试（ai_turn / ask / attachment / sampling / storage）
4. `describe` / `health` newline-delimited JSON smoke test
5. 检查仓库中没有 token、缓存、bundle 或本地 storage
