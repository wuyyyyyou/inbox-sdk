# 账号设置与智能搜索设计

## 目标与范围

为 Anna Inbox 增加按当前邮箱隔离的全页设置，并分两期交付：

- 一期：设置页、时间范围、时间分组、Important 的 Stars/Todos 置顶和数量设置，以及自定义分类的禁用 UI。
- 二期：自定义分类的实际筛选能力与智能搜索。

所有配置均以当前选中邮箱为边界保存；设置页不展示额外的账号级说明。同一套设置页在每个账号下保持一致，切换账号时读取该账号的配置。

## 一期交互与界面

### 入口与页面

- 在最右侧账号栏中，当前账号头像正下方新增齿轮按钮。
- 点击齿轮进入 `Settings` 全页；设置页覆盖 AI 侧栏和邮件工作区，账号栏保留。
- 设置页提供返回入口，返回此前的 Inbox。
- 在设置页切换账号时页面不变，只重新读取新账号的配置。
- 旧 `Sources` 抽屉及其 Mailboxes、Storage、删除数据与扫描策略内容全部移除；仅继承其视觉语言，不复用旧功能。

### 设置内容与默认值

按如下顺序展示，并在修改后立即保存：

1. `Display range`：7、30、60 天，默认 30 天。
2. `Time sections`：三种单选分组：
   - Today / Yesterday / Last 7 days / months；
   - Last 7 days / months；
   - months。
   默认第一种。
3. `Important priority`：Stars、Todos 各自有启用开关和数量选择，默认均启用、各显示 10 封。
4. `Custom categories`：展示创建分类、名称和查询条件的 UI，但输入、保存和应用入口全部禁用，并提示 `Coming soon`。

主页 Important 的内容顺序固定为 `Stars -> Todos -> 原有 Important 邮件`。仅展示启用的区块，且每个区块按配置数量截断。

### 持久化与失败处理

- 后端通过统一 storage 高层入口保存设置，以规范化邮箱地址隔离；并发更新使用 `etag` / `if_match`。
- 读取失败时使用默认值并显示可理解提示。
- 保存失败时恢复上一个已保存值并提供重试提示，避免界面与持久化数据不一致。
- 前端工具调用统一经 `mailAgentClient.ts` facade，不在组件中散落工具名称。

### 响应式行为

- 设置页在窄屏改为单列，账号栏保留。
- Important 置顶区与将来的自定义标签在空间不足时可横向滚动，不压缩邮件列表核心内容。

## 二期：自定义分类与智能搜索

### 自定义分类

- 用户填写分类名和查询条件后保存。
- 保存后的分类标签追加在主页 Inbox 的 `Important / Other` 后，不替代原有两个标签。
- 分类只基于当前账号、当前已同步且受展示范围限制的邮件。

### 搜索语法与结果

主页搜索框与分类查询编辑器共享同一套查询解析、建议和校验能力，支持：

- `subject:`：标题搜索；
- `body:`：正文搜索；
- `from:`：发件人搜索；
- `to:`：收件人搜索；
- 裸关键词搜索；
- `AND`、`OR` 组合条件；
- 不区分大小写的包含和前缀匹配，不实现拼写容错。

输入时展示对应操作符建议。结果中命中的发件人、主题、摘要以及已缓存的正文片段需要高亮。无匹配时显示可理解的无结果原因和修改建议。

搜索区域始终提示：仅搜索当前账号已同步的 X 天邮件。它不查询 Gmail 全量数据；正文搜索仅覆盖本地已缓存的正文内容。

## 验证

一期至少覆盖：

- 按账号读取和保存隔离；
- 默认值；
- 时间分组；
- Stars/Todos 的启用、顺序和数量；
- 读取/保存失败回退；
- 自定义分类禁用 UI。

完成实现后运行相关 Vitest 测试、`npm test` 和 `npm run build`。
