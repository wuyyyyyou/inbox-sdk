# Anna Inbox 2.0.17 架构与发布基线

## 产品基线

2.0 的主界面是三栏工作台：左侧 Anna AI Sidebar，中间 Inbox Workspace，右侧账户栏。点击邮件后，Mail Detail 从工作区右侧展开。

前端当前直接渲染 `HomeView`；旧 Brief、Ask 和 Handle React 组件仍保留，但不是 2.0 主导航。Brief 和 Ask 后端工具继续服务 AI 侧栏和兼容工作流。

设置入口现已恢复为按邮箱隔离的全页 Settings；旧 Sources 抽屉已移除，History 和 Memory 抽屉仍保留。

## 当前进度（2.0.17）

- **AI 侧栏统一 turn（阶段 A）**：默认经 Executa `start_ai_turn` 本地 Router 选型，白名单工具含 `chat_general`、`search_mail`（复用 Ask）、`summarize_thread`、`rank_answer`；前端组装只读 `ui_context`。可用 `localStorage anna-inbox-use-ai-turn=0` 回退旧 `aiRoute` 三分支。
- **Ask / Sampling 稳定性**：自定义扫描初等等待 60s、invoke 约 120s；候选正文并行读取；Answer JSON 本地修复加强（漏逗号、截断补括号）；失败摘要不向用户暴露 parser excerpt。
- **扫描范围**：AI 扫描默认对齐 Settings `display_range_days` 与 Scan Plan `max_messages`。
- 已接入 Anna Google Connected accounts：App 声明 `ui.host_api.credentials: ["google"]`，账户发现经 `credentials/listAccounts` Reverse RPC。
- Gmail token 仍仅在后端按 `account_id` 临时获取；不进入 iframe、APS KV 或本地存储。
- 多邮箱 registry、Inbox 设置、Splits、结构化搜索、Compose 草稿与发送守卫等能力沿用 2.0.16 基线。

### 未完成 / 后续阶段

- AI turn 阶段 B：草稿改写、`propose_inbox_actions` 确认卡片、Saved prompts / Memory。
- AI turn 阶段 C：批量 draft、删除前端业务路由死代码。
- Host Agent Session 不作为默认 LLM 路径。

## 代码边界

- `features/home/HomeView.tsx`：邮件列表、文件夹、AI 侧栏、账户切换和 Settings 入口。
- `app/useAppController.ts`：跨视图状态、缓存、轮询、AI 侧栏发送（`startAiTurn` / 旧路由旁路）。
- `api/mailAgentClient.ts`：前端唯一工具调用边界（含 `startAiTurn`）。
- `anna_inbox_executa/ai_turn_flow.py`、`mail_agent/ai_turn/`：统一 turn 入口与 Router/Runner。
- `anna_inbox_executa/`：JSON-RPC dispatcher 和长任务入口。
- `mail_agent/ask/`：Ask 规划、搜索和回答（search tool 复用）。
- `mail_agent/llm_runtime/service.py`：Sampling JSON 解析与修复。
- `mail_agent/mail_providers/gmail/adapter.py`：Gmail provider。
- `mail_agent/storage/`：统一持久化。

## 发布版本

以下位置必须一致：

- `anna-inbox/app.json`：`2.0.17`
- `inbox-tool/manifest.json`：`2.0.17`
- `inbox-tool/src/pyproject.toml`：`2.0.17`
- `anna-inbox/executas/inbox-tool/executa.json`：`2.0.17`
- `anna-inbox/manifest.json` required Executa min version：`2.0.17`
- `AGENTS.md`：`2.0.17`

## 发布门槛

1. `python scripts/sync/sync_executa_identity.py --check`
2. `npm test` 和 `npm run build`
3. 与改动相关的 Python 脚本测试（含 `test_llm_json_repair`、`test_ask_answer`、`test_ai_turn_router`）
4. `describe`、`health` newline-delimited JSON smoke test
5. 检查仓库中没有 token、缓存、bundle 或本地 storage

依赖真实 Gmail、Anna Host、APS 或在线 LLM 的验证必须明确标记为集成测试，不能把外部服务当作无条件可用。
