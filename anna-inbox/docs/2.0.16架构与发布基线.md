# Anna Inbox 2.0.16 架构与发布基线

## 产品基线

2.0 的主界面是三栏工作台：左侧 Anna AI Sidebar，中间 Inbox Workspace，右侧账户栏。点击邮件后，Mail Detail 从工作区右侧展开。

前端当前直接渲染 `HomeView`；旧 Brief、Ask 和 Handle React 组件仍保留，但不是 2.0 主导航。Brief 和 Ask 后端工具继续服务 AI 侧栏和兼容工作流。

设置入口现已恢复为按邮箱隔离的全页 Settings；旧 Sources 抽屉已移除，History 和 Memory 抽屉仍保留。

## 当前进度

- 已接入 Anna Google Connected accounts：App 声明 `ui.host_api.credentials: ["google"]`，账户发现经 `credentials/listAccounts` Reverse RPC 获取所有已授权账户。
- `list_mailboxes` 返回无敏感字段的 `credentials_status`；未授予 App Connected accounts 时，前端提示用户授权，不再静默显示默认单邮箱。
- Gmail token 仍仅在后端按 `account_id` 临时获取；不进入 iframe、APS KV 或本地存储。
- 已交付按当前邮箱隔离的 Inbox 设置：展示范围、时间分组与 Stars/Todos 置顶均由统一 storage 层以 `etag` 乐观并发控制保存；主页即时应用设置，保存失败会回滚并提示。
- 已交付自定义分类（Splits）管理：用户可在主页标签栏中新增、编辑和删除分类；分类按当前邮箱存储，并会在刷新时随 Inbox settings 一并加载。
- 已交付当前邮箱的结构化智能搜索：支持邮箱字段、状态、附件、日期和 `AND` / `OR` 组合，并提供操作符建议、错误反馈与结果高亮。
- 已交付本地 Compose 草稿的批量发送与 10 秒撤销窗口；发送仍须由用户明确确认触发。
- 多邮箱 registry 保留全部已选账户，第一个已选邮箱仅作为当前活动邮箱，不再反向取消其他已选邮箱，Brief 与 Ask 可据此聚合。

## 代码边界

- `features/home/HomeView.tsx`：邮件列表、文件夹、AI 侧栏、账户切换和 Settings 入口。
- `features/settings/`：按邮箱隔离的设置 DTO 纯函数、全页设置 UI 与 Splits 管理弹窗。
- `features/search/`：Inbox 结构化查询的解析、建议与本地筛选。
- `features/mail-detail/`：线程分页、正文、AI overview、草稿、附件。
- `app/useAppController.ts`：跨视图状态、缓存、轮询、设置读取/乐观保存和 mutation。
- `api/mailAgentClient.ts`：前端唯一工具调用边界。
- `anna_inbox_executa/`：JSON-RPC dispatcher 和长任务入口。
- `mail_agent/mail_providers/gmail/adapter.py`：Gmail provider。
- `mail_agent/storage/`：统一持久化，包括 Inbox settings。

## 发布版本

以下位置必须一致：

- `anna-inbox/app.json`：`2.0.16`
- `inbox-tool/manifest.json`：`2.0.16`
- `inbox-tool/src/pyproject.toml`：`2.0.16`
- `anna-inbox/executas/inbox-tool/executa.json`：`2.0.16`
- `anna-inbox/manifest.json` required Executa min version：`2.0.16`
- `AGENTS.md`：`2.0.16`

## 发布门槛

1. `python scripts/sync/sync_executa_identity.py --check`
2. `npm test` 和 `npm run build`
3. 与改动相关的 Python 脚本测试
4. `describe`、`health` newline-delimited JSON smoke test
5. 检查仓库中没有 token、缓存、bundle 或本地 storage

依赖真实 Gmail、Anna Host、APS 或在线 LLM 的验证必须明确标记为集成测试，不能把外部服务当作无条件可用。
