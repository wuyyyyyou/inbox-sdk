# 草稿 APS 同步说明

## 当前状态

为确保客户当前可稳定使用草稿功能，Gmail Draft 同步已暂时下线。草稿箱不再读取、创建、更新或删除 Gmail Draft；草稿仅通过 Anna APS 保存和跨设备恢复。

## 当前行为

- 用户保存、重新保存、批量保存和删除 Compose 草稿时，只操作 APS 中的 `compose-drafts` 数据及其已有附件元数据。
- 进入 Drafts 分类、刷新草稿和打开单封草稿时，只读取 APS；不会调用 Gmail Draft API，也不会展示 Gmail 草稿。
- Gmail 中已有草稿在本次临时方案期间不会出现在 Anna 的 Drafts 分类，也不会被 Anna 修改或删除。
- 原有 Gmail Draft API 实现不再由已暴露的 Compose 草稿工具调用，待同步问题修复并完成专项验证后再评估恢复。

## 本地镜像与异步同步

- Compose 草稿目录与邮件详情中的回复草稿会镜像到当前浏览器的 IndexedDB；打开草稿箱或编辑区时优先显示本地镜像，再在后台以 APS 最新结果覆盖，因此不会因网络往返延迟才显示草稿或“草稿”标签。
- 草稿内容、收件人、主题或附件没有改变时，关闭 Compose、关闭邮件详情编辑区不会触发 APS 写入；仅实际改动后的防抖保存或用户主动保存/删除/发送才会同步。
- 本地镜像仅保存草稿业务数据，不保存短期附件预览 URL；网络失败时继续保留已有本地草稿，等待用户恢复网络后手动重试。

## APS 失败处理

草稿目录读取是幂等操作。前端遇到 APS 网络类失败会自动重试多次；若仍失败，保留当前已显示的草稿列表，并提示用户检查网络环境后点击“重试”手动刷新。

保存、删除等写操作仍由用户显式触发；失败时按现有界面提示处理，避免在网络不确定时自动重复写入。

## 验收场景

1. 保存、编辑、批量保存和删除草稿后，数据只在 APS 中读写，不产生 Gmail Draft API 请求。
2. 进入 Drafts 分类时，仅展示 APS 中保存的 Compose 草稿。
3. 断网或 APS 不可达时，读取自动重试多次；仍失败时出现“检查网络环境后手动重试”的提示。
4. 网络恢复后，用户点击“重试”可重新加载 APS 草稿。
5. 刷新页面后，已有 Compose 草稿立即出现在 Drafts 分类；带 `source_thread_id` 的草稿立即让原收件箱会话显示“草稿”标签。
6. 未编辑草稿时关闭 Compose 或邮件详情编辑区，不发起 APS 保存请求；编辑后仍通过防抖异步保存。
