# Anna Inbox 2.0.18 架构与发布基线

## 产品基线

2.0 的主界面是三栏工作台：左侧 Anna AI Sidebar，中间 Inbox Workspace，右侧账户栏。点击邮件后，Mail Detail 从工作区右侧展开。

前端当前直接渲染 `HomeView`；旧 Brief、Ask 和 Handle React 组件仍保留，但不是 2.0 主导航。Brief 和 Ask 后端工具继续服务 AI 侧栏和兼容工作流。

设置入口为按邮箱隔离的 Settings；含 **AI Personalization**（Saved prompts / Memory）。History 和 Contact Memory 抽屉仍保留。

## 当前进度（2.0.18）

- **AI 侧栏统一 turn（阶段 A+B）**：
  - 默认 `start_ai_turn`：本地 Router + 白名单工具。
  - 阶段 A：`chat_general`、`search_mail`、`summarize_thread`、`rank_answer`、`clarify`。
  - 阶段 B：`draft_reply`、`revise_draft`、`summarize_then_draft`、`compose_new`、`propose_inbox_actions`、`remember_preference`。
  - 多轮：进程内 conversation registry（无正文）；`ui_context.last_draft` / `saved_prompt_id`。
  - 整理：`propose_inbox_actions` 仅建议；前端确认卡（Skip / 标为已处理等）→ `apply_proposed_actions`；`mark_done` 对齐 Inbox Done（mark_read + 本地 done）；确认后保留推荐列表与「是否继续」追问。
  - Saved prompts / AI Memory：APS/local KV；设置页 CRUD；输入框 ↑ 选择；Memory 注入 Router/写稿。
  - 旁路：`localStorage anna-inbox-use-ai-turn=0` 回退旧 `aiRoute`。
- **Ask / Sampling 稳定性**、扫描范围、Connected accounts 等沿用既有实现。

### 未完成 / 后续阶段

- AI turn 阶段 C：`batch_draft` / `batch_outreach`、删除前端业务路由死代码。
- Host Agent Session 不作为默认 LLM 路径。
- 日历 / MCP / 静默 mutation 仍不在本对话 Router 范围。

## 代码边界

- `features/home/HomeView.tsx`：邮件列表、AI 侧栏（确认卡 / Saved prompts）、账户切换和 Settings 入口。
- `features/settings/SettingsView.tsx`：Display range 与 AI Personalization。
- `app/useAppController.ts`：跨视图状态；`startAiTurn` / `applyProposedActions` / prompts & memory facade。
- `api/mailAgentClient.ts`：前端唯一工具调用边界。
- `anna_inbox_executa/ai_turn_flow.py`、`mail_agent/ai_turn/`：Router / Runner / tools / registry / personalization。
- `anna_inbox_executa/`：JSON-RPC dispatcher 和长任务入口。
- `mail_agent/ask/`：Ask 管线（search / propose 复用）。
- `mail_agent/storage/`：统一持久化。

## 发布门槛

1. `python scripts/sync/sync_executa_identity.py --check`
2. `npm test` 和 `npm run build`
3. 相关 Python 测试：`test_ai_turn_router`、`test_ai_turn_phase_b` 等
4. `describe`、`health` newline-delimited JSON smoke test
5. 检查仓库中没有 token、缓存、bundle 或本地 storage

依赖真实 Gmail、Anna Host、APS 或在线 LLM 的验证必须明确标记为集成测试。
