# Anna Inbox 2.1.9 架构与发布基线

## 产品基线

2.0 的主界面是三栏工作台：左侧 AI 侧栏，中间 Inbox Workspace，右侧账户栏。点击邮件后，Mail Detail 从工作区右侧展开。

对外称「AI 助理」：自然语言搜索、总结、写改稿、批量草稿和整理建议；整理、发送、删除和标签 mutation 均须明确用户操作确认。

## 当前版本（App 2.0.28 / Tool 2.1.9）

- Gmail History 增量同步：前台按邮箱设置同步第三方客户端的新邮件、删除、已读、星标、归档、重要和垃圾箱变更；cursor 过期时受控全量重建。
- Inbox 设置新增自动刷新间隔：关闭、15 秒、30 秒、60 秒、120 秒，默认 15 秒。
- 自动同步在邮件详情抽屉打开期间只更新后端缓存，关闭后再刷新中间邮件列表，避免详情正文和滚动位置抖动。
- Runtime transport 失效后单飞重连；安全读取可在新连接重试，邮件 mutation 不自动重放。
- AI Thinking 气泡展示实时耗时，最终消息在时间右侧保留耗时。
- 线程详情仅在完整本地线程缓存可用时复用缓存；长线程缓存不完整或用户点击 Update thread 时强制从 Gmail 刷新。
- 平台调用链安全诊断：同步 invoke 与后台 AI run 返回独立 trace，覆盖 `credentials.list_accounts`、`credentials.get_token`、`gmail.token`、`gmail.http`、`sampling.create_message` 和 `executa.invoke`。
- 前端只在失败消息中展示格式校验后的安全 trace 阶段摘要；邮件、地址、提示词、模型输出和凭据均不进入诊断。
- AI 侧栏 Ask 仅检索当前活动邮箱，忽略 `selected_mailboxes`，避免多账户选择状态扩大搜索与平台凭据调用。
- Ask 全文缓存 worker 复制本次 Gmail 请求上下文，复用短期 token 和诊断 trace，避免逐封触发 `credentials/getToken`。
- 多邮箱切换保留临时故障前的 Connected Accounts 映射；非默认邮箱不可退回未验证归属的默认 token。

## 代码边界

- `mail_agent/mail_providers/gmail/adapter.py`：Gmail History cursor、All-mail 缓存和平台 token 复用。
- `anna_inbox_executa/gmail_tools.py`、`dispatcher.py`：`sync_inbox_cache` 工具入口。
- `app/useAppController.ts`：自动同步调度、详情抽屉延迟列表刷新和 runtime 重连。
- `api/mailAgentClient.ts`：统一工具调用、transport 错误识别和安全读取重试。
- `features/mail-detail/`：线程缓存完整性和强制刷新。
- `features/settings/`：自动刷新间隔设置。
- `anna_inbox_executa/diagnostics.py`：调用上下文隔离的安全时序 trace。
- `mail_agent/mail_providers/gmail/adapter.py`、`sampling_tools.py`、`common.py`：Gmail、Sampling 与 Connected accounts 阶段计时。
