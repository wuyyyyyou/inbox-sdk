# Anna Inbox 2.1.5 架构与发布基线

## 产品基线

2.0 的主界面是三栏工作台：左侧 Anna AI Sidebar，中间 Inbox Workspace，右侧账户栏。点击邮件后，Mail Detail 从工作区右侧展开。

前端当前直接渲染 `HomeView`；旧 Brief、Ask 和 Handle React 组件仍保留，但不是 2.0 主导航。Brief 和 Ask 后端工具继续服务 AI 侧栏和兼容工作流。

设置入口为按邮箱隔离的 Settings；含 **AI Personalization**（Saved prompts / Memory）与 **Connectivity check**（LLM / Gmail API 轮询间隔）。History 和 Contact Memory 抽屉仍保留。

## 当前进度（App 2.0.24 / Tool 2.1.5）

- **AI 侧栏显示与草稿（App）**：
  - 助手回复先完整解析 Markdown，再按稳定 AST 揭示，避免半截 Markdown 重解析导致列表/段落乱序。
  - `Replace draft reply` 直接覆盖邮件详情编辑栏内容，不复用 Discard；Replace / Discard 后禁止当前线程旧持久化草稿自动回填。
  - Discard 首次点击立即清空并关闭，不再因异步草稿读取而重新展开。
  - 侧栏与抽屉统一 `thread_id || id` 线程标识；点击替换时绑定匹配邮件抽屉。
  - 搜索状态文案优先跟随用户请求语言；会话可续跑 `pendingRun` / `resumeAiConversation`。
- **Ask / Router 准确性（Tool）**：
  - 指定联系人请求保留 `from:` / `to:` 精确条件，无命中时不自动放宽为泛收件箱扫描。
  - Router 将明确收件箱检索意图从纯聊天覆盖到 `search_mail`。
  - Planner / Answer 用户可见文案按请求语言校验；英文请求避免中文标题/摘要污染前端状态文案。
- **设置与 Splits（App）**：
  - Settings / Splits 操作按钮样式与保存、删除 toast 反馈。
- **连通性与 AI turn（既有）**：沿用 2.1.4 反向 RPC 直通、12 秒检测预算、`start_ai_turn` 阶段 A+B。

### 未完成 / 后续阶段

- AI turn 阶段 C：`batch_draft` / `batch_outreach`、删除前端业务路由死代码。
- Host Agent Session 不作为默认 LLM 路径。
- 日历 / MCP / 静默 mutation 仍不在本对话 Router 范围。

## 代码边界

- `features/home/HomeView.tsx`：邮件列表、AI 侧栏、稳定打字机、草稿替换入口。
- `features/home/aiMessageFormatting.ts`：Markdown 解析与按字符预算切片。
- `features/mail-detail/MailDetailDrawer.tsx`：编辑栏草稿、Replace / Discard、禁止自动回填。
- `app/useAppController.ts`：跨视图状态；`startAiTurn` / `resumeAiConversation` / connectivity。
- `mail_agent/ask/search.py`、`answer.py`、`planner.py`：Ask 检索与回答边界。
- `mail_agent/ai_turn/router.py`：检索意图覆盖与白名单路由。

## 发布门槛

1. `python scripts/sync/sync_executa_identity.py --check`
2. `npm test` 和 `npm run build`
3. 相关 Python 测试：`test_ask_search`、`test_ask_answer`、`test_ai_turn_router` 等
4. `describe`、`health` newline-delimited JSON smoke test
5. 检查仓库中没有 token、缓存、bundle 或本地 storage

依赖真实 Gmail、Anna Host、APS 或在线 LLM 的验证必须明确标记为集成测试。
