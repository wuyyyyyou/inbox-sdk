# Anna Inbox 2.0.14 架构与发布基线

## 产品基线

2.0 的主界面是三栏工作台：左侧 Anna AI Sidebar，中间 Inbox Workspace，右侧账户栏。点击邮件后，Mail Detail 从工作区右侧展开。

前端当前直接渲染 `HomeView`；旧 Brief、Ask 和 Handle React 组件仍保留，但不是 2.0 主导航。Brief 和 Ask 后端工具继续服务 AI 侧栏和兼容工作流。

设置入口在 2.0.1 暂时隐藏，配置 drawer、API 和存储结构没有删除。

## 当前进度

- 已接入 Anna Google Connected accounts：App 声明 `ui.host_api.credentials: ["google"]`，账户发现经 `credentials/listAccounts` Reverse RPC 获取所有已授权账户。
- `list_mailboxes` 返回无敏感字段的 `credentials_status`；未授予 App Connected accounts 时，前端提示用户授权，不再静默显示默认单邮箱。
- Gmail token 仍仅在后端按 `account_id` 临时获取；不进入 iframe、APS KV 或本地存储。

## 代码边界

- `features/home/HomeView.tsx`：邮件列表、文件夹、AI 侧栏、账户切换。
- `features/mail-detail/`：线程分页、正文、AI overview、草稿、附件。
- `app/useAppController.ts`：跨视图状态、缓存、轮询和 mutation。
- `api/mailAgentClient.ts`：前端唯一工具调用边界。
- `anna_inbox_executa/`：JSON-RPC dispatcher 和长任务入口。
- `mail_agent/mail_providers/gmail/adapter.py`：Gmail provider。
- `mail_agent/storage/`：统一持久化。

## 发布版本

以下位置必须一致：

- `anna-inbox/app.json`：`2.0.14`
- `inbox-tool/manifest.json`：`2.0.14`
- `inbox-tool/src/pyproject.toml`：`2.0.14`
- `anna-inbox/executas/inbox-tool/executa.json`：`2.0.14`
- `anna-inbox/manifest.json` required Executa min version：`2.0.14`
- `AGENTS.md`：`2.0.14`

## 发布门槛

1. `python scripts/sync/sync_executa_identity.py --check`
2. `npm test` 和 `npm run build`
3. 与改动相关的 Python 脚本测试
4. `describe`、`health` newline-delimited JSON smoke test
5. 检查仓库中没有 token、缓存、bundle 或本地 storage

依赖真实 Gmail、Anna Host、APS 或在线 LLM 的验证必须明确标记为集成测试，不能把外部服务当作无条件可用。
