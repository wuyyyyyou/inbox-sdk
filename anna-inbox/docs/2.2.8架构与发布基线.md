# Anna Inbox 2.2.8 架构与发布基线

## 产品基线

2.0 的主界面是三栏工作台：左侧 AI 侧栏，中间 Inbox Workspace，右侧账户栏。点击邮件后，Mail Detail 从工作区右侧展开。

**唯一智能入口**为 Anna AI Sidebar：默认 Host Agent Session；本地可用 `source=sidebar_local` 兼容路径。Brief 产品面下线。整理、发送、删除和标签 mutation 均须明确用户操作确认。

## 当前版本（App 2.1.8 / Tool 2.2.8）

### 列表分页（本版本）

- 移除 Settings `Initial list size`；前端固定 `INBOX_FEED_PAGE_SIZE=100`，**不**进入后端同步逻辑。
- 当前时间窗内更多：列表 `.mail-feed` **触底自动加载**（抬 `localLimit`，不足再续缓存/Gmail）；**不展示** Show more 按钮。
- 所有分类共用分页（Inbox / Important / Other / 自定义 Split / Todos / Snoozed / Done 等）；切换标签时 `localLimit` 重置为 100。
- Inbox 标签角标计数 `> 99` 显示 `99+`；不截断真实列表。
- `ALL_MAIL_CACHE_FETCH_LIMIT=400` 仅 UI 快照 RPC；AI 检索扫全量本地缓存，不受此限。
- 扩大时间窗（7→30→60→All）仍为底部手动按钮。

### 邮箱同步：缓存优先（P0）

- 列表 `display_range_days`（7/30/60）**仅**控制 Inbox 展示投影，不限制 AI 检索范围。
- 首次连接 / 清缓存后优先同步最近 **180 天** All-mail **metadata**；更早历史后台无硬顶 backfill，page token 可断点续跑。
- `sync_inbox_cache` 用 History 增量合并；可选 Gmail Watch 注册；前端 `auto_sync_seconds`（默认 15s）轮询兜底。
- 每个邮箱暴露 `sync_boundary`；禁止把索引诊断原文当作用户答案。
- 实现：`mailbox_sync.py`、`gmail_tools.py`、`adapter.py`；前端 `silentSyncInbox`。

### AI 只读取证：`query_mail_evidence`

- Host / local 侧栏主路径：邮箱范围问答**只调一次** `query_mail_evidence`。
- `search_email` / `read_email`：cache-only；`order=oldest|newest`；`bodyFull` 未同步时 `body_pending`。
- 用户明确时间目标早于 `earliest_indexed_at` 时，Evidence 可一次受限 Gmail 历史检索（最多 20）。
- `display_range_days` 不得写入 Agent 选型上下文作为检索边界。

### 正文 / 附件预处理、侧栏 local、草稿与详情

- 后台 `content_preprocess` / `preprocess_cached_content_batch`（含 `pypdf`）。
- local 调试：`start_ai_turn(source=sidebar_local)` + 与 Host 相同工具白名单。
- 草稿卡片可编辑插入；详情滚到线程底部；列表短暂丢消息不关抽屉。

### 继承能力

- 邮箱级 workflow state / AI Ask history（乐观并发 etag）。
- 收件附件 Host transient upload → APS Files；reverse-RPC 超时约 20s。
- 联系人头像仅 People API；平台安全 trace。
