# Anna Inbox 2.2.6 架构与发布基线

## 产品基线

2.0 的主界面是三栏工作台：左侧 AI 侧栏，中间 Inbox Workspace，右侧账户栏。点击邮件后，Mail Detail 从工作区右侧展开。

**唯一智能入口**为 Anna AI Sidebar（`start_ai_turn` / Host Agent Session）：自然语言搜索、总结、写改稿、整理建议。Brief 产品面下线。整理、发送、删除和标签 mutation 均须明确用户操作确认。

## 当前版本（App 2.1.6 / Tool 2.2.6）

### search_email 摘要预算与请求超时

- `search_email` 仍使用标准 Gmail 查询实时检索，不回退本地缓存。
- 普通搜索的 Gmail 候选数等于返回 `limit`，避免一次工具调用放大为数十次 metadata 请求。
- 含本地工作流筛选（`is:todo` / `is:done` / `is:snoozed`）时候选上限 60（`max(limit * 3, 20)`），仅 AND。
- 列表 / 摘要 / token 请求支持 `request_timeout_seconds`；Agent 搜索默认 12s。
- 单次返回硬上限 20 条轻量字段（date / participants / subject / bodySnippet + THREAD_REF）。
- Gmail 失败时向用户说明错误，不伪装成空缓存。

### 邮箱级工作流状态与 AI Ask 历史

- 新增工具：`get_inbox_workflow_state` / `save_inbox_workflow_state`、`get_ai_ask_history` / `save_ai_ask_history`。
- 存储 key 按 mailbox 隔离（`inbox_workflow_state`、`ask_history`）；保存使用 `if_match` 乐观并发。
- Workflow 状态规范化：Todo 优先于 Done，Snoozed 与二者互斥；message_id 去重并限制体积。
- Ask 历史最多保留 30 条由前端裁剪后的 entries。

### 列表加载更多与后台同步

- `HomeView`：`canShowMoreEmails` / 扩大时间范围在 `feedAction === "refresh"` 时仍可用。
- 同步中按钮文案为 `Syncing...`；显式 more/expand 仍由 `feedAction` 与 `isInboxSyncing` 禁用。

### 继承能力

- Host Agent Session 流式会话、白名单工具、取消/恢复；详情/兼容路径保留本地 Router 与 `start_ai_turn`。
- 收件附件优先 Host transient upload，失败回退 APS Files；reverse-RPC 超时约 20s。
- 邮件详情打开后固定滚到底部；inline/CID 不计入下载附件。
- 联系人头像仅 Google People / 账户头像；缓存刷新后预热。
- Sampling grant 预算快照；多邮箱切换与 History 静默同步；平台安全 trace 诊断。

## 代码边界

- `anna_inbox_executa/ai_agent_tools_flow.py`、`mail_agent/local_query.py`：Agent 搜索与本地工作流过滤。
- `mail_agent/mail_providers/gmail/adapter.py`：Gmail 搜索、摘要、可配置 HTTP/token 超时。
- `mail_agent/storage/ops.py`、`anna_inbox_executa/v2_tools.py`、`common.py`：workflow state 与 Ask history 读写。
- `features/home/HomeView.tsx`：列表加载更多与后台 refresh 交互。

2. `cd anna-inbox && npm test && npm run build`
3. 相关 Python 脚本式测试（`test_ai_agent_tools` 等）
4. `describe` / `health` newline-delimited JSON smoke test
5. 检查仓库中没有 token、缓存、bundle 或本地 storage
