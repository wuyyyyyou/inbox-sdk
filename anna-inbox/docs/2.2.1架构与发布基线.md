# Anna Inbox 2.2.1 架构与发布基线

## 产品基线

2.0 的主界面是三栏工作台：左侧 AI 侧栏，中间 Inbox Workspace，右侧账户栏。点击邮件后，Mail Detail 从工作区右侧展开。

对外称「AI 助理」：自然语言搜索、总结、写改稿、批量草稿和整理建议；整理、发送、删除和标签 mutation 均须明确用户操作确认。

## 当前版本（App 2.1.1 / Tool 2.2.1）

### 外发与撰写

- 回复 / 转发 / Compose 支持多附件：`begin_stage_outgoing_attachment` → loopback PUT → 草稿只存元数据 → 发送时组 MIME；合计 ≤25MB，拦截可执行/脚本扩展名。
- 回复与 Compose 支持 Cc / Bcc；详情区支持 Reply / Reply all / Forward 模式切换与独立草稿状态。
- 发送前 10 秒可撤销（PendingSendScheduler）；撤销后不落 Gmail。
- 收件人输入使用 chip 组件；外发附件条统一 `OutgoingAttachmentBar`。

### 多邮箱与凭据

- 切换邮箱立刻 `cancel_mail_agent_run` 停上一扫描；UI 先读 `list_cached_emails`，后台 `silentSyncInbox`（History；仅 resync 时回源）。
- `gmail_request` 遇 HTTP 401：清空 ContextVar 短期 token，`force_refresh=True` 换票后仅重试一次。
- 平台 `credentials/getToken` 全进程串行，降低多邮箱并发换票踩踏。
- 冷启动/切换路径对瞬时 401 再试一次，不整页回滚到上一邮箱。

### 收件附件与列表

- metadata / History 合并保留完整附件树；详情补齐附件后回填首页摘要与 feed 页回形针。
- `prepare_*_attachment_*` 缓存 miss 时回源 `fetch_and_cache_message`。
- 移除手动「Update thread」横幅；长线程或附件元数据缺失时后台/按需刷新。

### Ask / Brief

- Ask 模糊「最近」不覆盖 Scan Plan 窗口；「需要浏览/处理」走 broad sweep + 回答排序。
- `cancel_mail_agent_run` 取消 Brief/Ask 后台 run，切换邮箱释放 getToken/Gmail。

### 继承能力

- Gmail History 增量同步、自动刷新间隔、详情打开期间延迟列表刷新。
- Runtime transport 单飞重连；AI Thinking 耗时；平台安全 trace 诊断。
- AI 侧栏 Ask 仅检索当前活动邮箱。

## 代码边界

- `mail_agent/mail_providers/gmail/outgoing_attachments.py`：外发 stage、校验、发送装载。
- `mail_agent/mail_providers/gmail/adapter.py`：401 force_refresh、token scope 绑定邮箱、附件摘要回填、发送 MIME。
- `anna_inbox_executa/v2_tools.py`：stage 工具、loopback PUT、回复 Cc/Bcc/附件。
- `anna_inbox_executa/brief_flow.py`：`cancel_mail_agent_run`。
- `anna_inbox_executa/common.py`：getToken 串行锁、manifest 新工具。
- `app/useAppController.ts`：丝滑切换、silent 同步、取消扫描、附件列表 patch。
- `features/home/ComposeView.tsx`、`features/mail-detail/MailDetailDrawer.tsx`、`shared/OutgoingAttachmentBar.tsx`、`shared/RecipientChipInput.tsx`、`features/home/pendingSend.ts`。
- `mail_agent/ask/planner.py`、`answer.py`：时间窗与 actionable 意图。
