# 多邮箱接入

## 当前状态

2.0.1 支持发现和切换多个 Gmail 邮箱。账户栏读取 mailbox registry，只展示授权有效的邮箱；切换后重新加载对应邮箱的列表、缓存和草稿。

## 发现来源

- Anna `credentials/listAccounts` Reverse RPC：返回所有已授权 Google 账户的 metadata（`account_id`、email、默认标记与状态），是平台多邮箱模式的权威来源。
- Anna `credentials/getToken` Reverse RPC：每次 Gmail 请求按目标账户的 `account_id` 交换短期 access token。token 不进入前端、不写入 APS/local storage，刷新由平台处理。
- App manifest 必须声明 `ui.host_api.credentials: ["google"]`；生产环境还需在 Anna 为该 App 授予 Google Connected accounts，授权账号本身与 App grant 是两层权限。
- 平台旧式单账号 credential 与本地开发 token 文件仅作为兼容回退。
- 本地开发的 `scripts/google_token/.secrets/gmail_tokens/`，或 `ANNA_INBOX_TOKEN_DIR`。

Registry 只保存邮箱地址、provider、选择状态、授权状态和扫描元数据，不保存 token 或平台 account id。

## 隔离边界

- Gmail cache、cards、scan state、drafts 和 contact memory 均按 mailbox 隔离。
- 邮件操作必须使用目标 message/card 自身的 mailbox，不能依赖全局默认邮箱。
- 前端复合 key 使用 mailbox + message/card/thread ID，避免跨账户碰撞。

## 当前限制

- provider 仅为 Gmail。
- Inbox Workspace 当前一次展示一个活动邮箱，通过账户栏切换。
- 设置入口暂时隐藏，因此用户不能从 2.0.1 UI 编辑完整 registry 或 Scan Plan。
- 平台需要 v1.1.0-beta.84+，并通过 Executa protocol 2.0 提供 credentials Reverse RPC；用户授权 Gmail 所需 scope 后，账户可在 Anna Settings → Authorizations 中独立刷新、重连或断开。
- `list_mailboxes` 会返回无敏感字段的 `credentials_status`：`not_granted` 表示需授予 Google Connected accounts，`protocol_unsupported` 表示需升级运行时。该状态只含 `code`、`message` 和 `action`，绝不返回 token。
