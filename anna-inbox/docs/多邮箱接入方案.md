# 多邮箱接入方案（修订版）

> **状态：大部分已实施。** MailboxRegistry、selectedMailboxes、多邮箱扫描、聚合卡片、checkbox 勾选模型均已实现。前端引用的是旧架构（`app.js`），当前为 React 组件。Ask 快速勾选、按邮箱 Scan Plan 等细节已实施。

## 核心设计决策

**勾选模型替代 activeMailboxId 单选模型。** 用户在 Sources 抽屉中对每个邮箱进行 checkbox 勾选，Brief 只扫描勾选的邮箱，卡片列表只展示勾选邮箱的卡片。不再保留 `activeMailboxId` 的"All / 单邮箱"切换逻辑。

---

## 一、邮箱发现

### 1.1 本地 dev

扫描 `scripts/google_token/.secrets/gmail_tokens/` 目录下所有 token 文件，每个文件对应一个可用邮箱。调用 Gmail profile API 获取实际邮箱地址。

### 1.2 Anna 平台

通过平台注入的 OAuth token 调用 Gmail profile API 获取授权邮箱。当前平台只支持单 token，因此只发现一个邮箱。后续平台支持多 token 后自动扩展。

### 1.3 展示位置：Sources 抽屉

Sources 抽屉成为邮箱管理的唯一入口。每个邮箱显示：

- 邮箱地址
- Provider（Gmail / 未来 Outlook）
- 授权状态（Connected / Re-auth needed）
- 上次扫描时间
- **checkbox（默认勾选）**

底部提供操作入口：添加邮箱引导、移除邮箱、重新授权引导。

## 二、勾选模型

### 2.1 状态定义

```typescript
// AppState 中
mailboxes: MailboxInfo[];               // 所有已注册邮箱（含 selected、授权状态等字段）
selectedMailboxes: string[];            // 当前勾选的邮箱地址（从 registry.selected 恢复）
mailboxAuth: Record<string, AuthStatus>; // 每个邮箱的授权状态
```

不再保留 `activeMailboxId`。

`state.mailbox` 保留但语义降级：仅作为"默认/主要邮箱"用于 Ask 等需要单个邮箱目标的操作。当 `selectedMailboxes` 非空时，取第一个作为默认。

### 2.2 交互规则

- Sources 抽屉中每个邮箱一个 checkbox
- 默认全选
- 取消勾选邮箱 C → 邮箱 C 的卡片从列表中消失
- 重新勾选邮箱 C → 邮箱 C 的卡片重新显示
- 取消所有勾选 → 空列表，Brief 按钮禁用

### 2.3 持久化

`selectedMailboxes` 持久化到后端存储（APS 或 local），与 mailbox registry、scan plan 等数据一致。`mailbox-registry` 中增加 `selected` 字段：

```json
{
  "mailboxes": [
    {"email": "a@gmail.com", "selected": true, ...},
    {"email": "b@company.com", "selected": true, ...},
    {"email": "c@gmail.com", "selected": false, ...}
  ]
}
```

每次勾选变更时调用后端接口同步。初始化时从 registry 恢复勾选状态。不依赖浏览器 localStorage。

## 三、Brief 扫描

### 3.1 扫描范围

只对 `selectedMailboxes` 中的邮箱执行扫描，不扫描未勾选的邮箱。

- 全选 → 对所有邮箱依次扫描
- 只勾选 A、B → 只扫 A 和 B
- 勾选发生变化时，已扫描结果保留；新勾选的邮箱需要一次独立扫描才能产卡

### 3.2 串行扫描 + 渐进展示

**当前设计为串行**（未来再优化为并行）。

#### 第一个邮箱

正常显示全屏扫描进度动画（scanning stage、judging、完成百分比等），与当前单邮箱行为一致。

#### 第一个邮箱完成后

- 立即展示该邮箱产出的 cards（调用 `loadActiveCards` 加载已完成的邮箱）
- 不再显示全屏进度动画

#### 后续邮箱

进度仅在底部状态栏显示，例如：

```
Scanning b@company.com · 2/3 mailboxes done
```

用户可以在第一个邮箱的 cards 上操作，同时底部栏显示后续邮箱的扫描进度。

#### 全部完成

底部栏消失，或显示汇总：

```
3/3 mailboxes scanned · a@gmail.com (5 cards) · b@company.com (3 cards) · c@gmail.com (failed: token expired)
```

### 3.3 扫描失败处理

某个邮箱扫描失败不影响其他邮箱。失败邮箱在 Sources 抽屉中标记错误状态，底部栏显示失败原因。

### 3.4 增量扫描

每个邮箱独立维护其 `processed_message_ids` 和 `scan_state`。增量扫描时各邮箱只处理自己的新邮件，互不干扰。

### 3.5 未来并行优化思路

后端用 `asyncio.gather` 并发执行多个邮箱的 pipeline（semaphore 限制并发数 2-3，避免触发 Gmail API 速率限制）。前端同时展示多路进度（每个邮箱一行：queued / scanning / judging / done / failed）。LLM 调用量成倍增长，需评估成本。

## 四、卡片展示

### 4.1 聚合加载

初始化时调用 `get_active_cards(mailbox="all")` 聚合所有已注册邮箱的 active cards，后端遍历 registry 中所有邮箱，合并后按 `updated_at` 降序返回。

### 4.2 前端筛选

从聚合的 cards 中筛选 `card.details.mailbox in selectedMailboxes`。不展示未勾选邮箱的卡片。

### 4.3 邮箱标签

在混合视图中，每张卡片显示来源邮箱标签（小 chip），方便用户区分。当 `selectedMailboxes.length === 1` 时可隐藏标签（因为全是同一邮箱）。

### 4.4 分类筛选

现有的分类筛选（All / Needs reply / Needs review / Cleanup）在聚合卡片上跨邮箱生效。

## 五、卡片操作

### 5.1 核心原则

**所有卡片操作使用 `card.details.mailbox`，不使用 `state.mailbox`。**

### 5.2 需要修改的操作

| 操作 | 当前行为 | 修改后 |
|---|---|---|
| `openCard` | 传 `state.mailbox` | 传 `card.details.mailbox` |
| `generateDraft` | 传 `state.mailbox` | 传 `card.details.mailbox` |
| `recordDecision` | 传 `state.mailbox` | 传 `card.details.mailbox` |
| `replyNow` | 传 `state.mailbox` | 传 `card.details.mailbox` |
| `markCleanupAsRead` | 传 `state.mailbox` | 传 `card.details.mailbox` |
| `restoreCard` | 传 `state.mailbox` | 传 `card.details.mailbox` |
| `snoozeCard` | 传 `state.mailbox` | 传 `card.details.mailbox` |

### 5.3 Ask 结果操作

Ask 返回的 `CustomRunResultItem` 需携带 `mailbox` 字段。Ask 的 Mark read、Trash、Reply 均使用 `item.mailbox`。

### 5.4 卡片 key 前缀

前端按 `cardId` 存储的状态 map（`draftById`、`revisionById`、`replyModeById`、`expandedDetails`、`cleanupReadState`、`markingReadIds`）建议统一使用 `${mailbox}::${cardId}` 作为 key，避免不同邮箱卡片 ID 碰撞。

## 六、Sources 抽屉

### 6.1 结构

```
┌─ Mailboxes ───────────────────────────┐
│                                        │
│  ☑ a@gmail.com          ✓ connected   │
│     Last scan: 10 min ago · 5 cards   │
│                                        │
│  ☑ b@company.com        ✓ connected   │
│     Last scan: 1 hour ago · 3 cards   │
│                                        │
│  ☐ c@gmail.com          ⚠ re-auth    │
│     Token expired. Reconnect →        │
│                                        │
│  [+ Add another mailbox...]           │
│                                        │
│  ──────────────────────────────────── │
│  ☑ Select all / ☐ Deselect all       │
└────────────────────────────────────────┘
```

### 6.2 邮箱发现与展示

- **本地 dev**：扫描 `gmail_tokens/` 目录，列出所有有 token 文件的邮箱
- **Anna 平台**：展示平台注入的授权邮箱列表（当前 1 个）
- 每个邮箱独立校验授权状态，展示在对应行

### 6.3 添加邮箱

- **本地 dev**：引导用户运行 `gmail_local_oauth.py` 为新的 Gmail 授权，然后将 token 文件放入 `gmail_tokens/` 目录。前端提供"Refresh"按钮重新扫描 token 目录
- **Anna 平台**：引导用户去 Anna Authorizations 面板添加 Google 账号。如果平台不支持多账号，则在 UI 上明确说明限制，不伪装成可用

验证规则：`add_mailbox` 必须校验 `get_authorized_email() === mailbox`，不允许注册未被当前 token 授权的邮箱。

### 6.4 移除邮箱

调用 `remove_mailbox(mailbox)`，从 registry 中移除，同时从 `selectedMailboxes` 中移除。该邮箱的存储数据保留（不删除），以便重新添加后恢复。

### 6.5 重新授权

如果 Anna 平台不支持从 app 直接发起 OAuth，给出明确引导：
- 打开 Anna Authorizations
- 选择 Google，确认 Gmail scope
- 返回后点击 Check again

## 七、Ask 和 Scan Plan 语义

### 7.1 Ask

#### 执行范围

Ask 对**所有勾选邮箱**执行，与 Brief 一致。Planner 生成一份覆盖所有勾选邮箱的计划（如 "在 A、B 中查找关于 Q3 预算的邮件"），执行完成后聚合展示结果，每条结果标明所属邮箱。

#### 快速勾选

Ask 输入框旁边有一个快速勾选入口（小型 checkbox 列表），允许用户临时选择本次 Ask 的目标邮箱：

- **默认值**：App 重新打开时，从 Sources 持久化勾选状态同步；同一会话内，记住用户上次在 Ask 中的选择
- **仅本次生效**：Ask 快速勾选的修改不写回 Sources 持久化状态，不影响 Brief 扫描范围
- **下次打开**：App 重启后重新从 Sources 同步

#### 进度展示

聚合展示，不按邮箱拆分进度动画。与当前单邮箱 Ask 的进度展示一致。

### 7.2 Scan Plan

- Scan Plan 按邮箱独立存储（`scanPlans: Record<string, ScanPlan>`）
- Sources 抽屉中可进入每个邮箱的 Scan Plan 配置
- 暂不支持全局 Scan Plan（避免语义混乱）。未来如果有需求，单独建 `global_scan_plan` key

### 7.3 Run History

- Run history 保持全局 key（`runs/history`），每条记录携带 `mailbox` 字段
- 前端在 Sources 抽屉的单邮箱视图中可按邮箱筛选
- 全局视图中每条记录显示 mailbox tag

### 7.4 用户偏好

`Don't prioritize threads like this` 等偏好默认只对当前邮箱生效，UI 文案写明 `Don't prioritize this sender in a@gmail.com`。未来再加全局选项。

## 八、授权模型

### 8.1 校验规则

`_check_gmail_auth(mailbox)` 在平台环境下：
1. 调 Gmail profile 获取 authorized email
2. 如果传入 mailbox 不等于 profile email，返回 unauthorized

`add_mailbox(mailbox)` 在平台环境下：
1. 先调 `_check_gmail_auth(mailbox)`
2. 只有 authorized 才允许写入 registry

这样可以避免"一个平台 token 授权所有邮箱"的误判。

### 8.2 本地 dev

`get_access_token(mailbox)` 按邮箱读取对应的 token 文件：
```
scripts/google_token/.secrets/gmail_tokens/<sanitized_mailbox>.json
```
多 Gmail 在本地是可实现的。

### 8.3 MailboxRegistry 数据格式

```json
{
  "mailboxes": [
    {
      "email": "a@gmail.com",
      "provider": "gmail",
      "auth_source": "platform",
      "authorized": true,
      "selected": true,
      "last_auth_checked_at": "2026-06-03T16:00:00+08:00",
      "last_scan_at": null,
      "last_error": null
    }
  ]
}
```

`selected` 字段随用户勾选变更同步到后端存储，初始化时从 registry 恢复。

注意：不把 token 写进 registry。registry 只保存状态和元数据。

## 九、数据流总览

```
初始化:
  list_mailboxes() → 获取注册邮箱列表（包含 selected 字段）
  discover_available_mailboxes() → 本地扫描 token 目录 / 平台获取注入邮箱
  合并去重 → mailboxes[]
  selectedMailboxes = registry 中 selected=true 的邮箱（首次默认全选，同步到后端）
  逐一 checkGmailAuth → mailboxAuth[email]
  loadActiveCards("all") → 聚合所有邮箱卡片
  loadScanPlans(各邮箱)

Brief 扫描:
  startScan() → for each mailbox in selectedMailboxes (串行):
    start_mail_agent_run(mailbox)
    poll until done
    第一个邮箱: 全屏进度动画
    后续邮箱: 底部栏进度
  全部完成 → loadActiveCards("all") → 刷新卡片列表

Ask 扫描:
  startCustomScan() → 对 askMailboxes（Ask 快速勾选）一起执行 plan-and-execute
  Planner 生成一份覆盖所有目标邮箱的计划
  聚合结果展示，每条结果标明所属邮箱

切换 Sources 勾选:
  selectedMailboxes 更新 → 前端 filter cards + 同步写入后端 registry
  同一会话内不影响 Ask 快速勾选；App 重启后 Ask 从 Sources 同步

卡片操作:
  card.details.mailbox → 传给后端工具
```

## 十二、设计原则

1. **卡片操作以 `card.details.mailbox` 为准**，不依赖 `state.mailbox`。
2. **授权状态以真实 token 所属账号为准**，不以 registry 字符串为准。
3. **未勾选 = 不参与**：不扫描、不展示卡片、不消耗 API 配额。
4. **Sources 勾选持久化到后端**，变更时同步写入 registry；勾选变更不触发重新扫描，已加载的卡片通过前端 filter 控制可见性。
5. **Ask 快速勾选独立于 Sources**：同一会话内记忆，App 重启后从 Sources 同步，仅影响 Ask 不写回 Sources。
6. **如果平台暂不支持多账号 OAuth，在 UI 上明确限制**，不伪装成可用。

## 十三、优化建议

### 13.1 明确 MVP 边界

第一版建议按"本地 dev 真多邮箱，Anna 平台单授权邮箱"落地。平台侧如果当前只注入一个 Gmail OAuth token，就不要在平台 UI 中展示"可同时添加多个 Gmail"的承诺，只展示：

- 当前已授权邮箱
- 添加邮箱的入口说明
- 如果平台不支持多账号 OAuth，明确提示"当前 Anna 平台只允许当前授权账号参与扫描"

这样可以避免用户以为已经接入多个邮箱，但实际所有 Gmail API 调用都落到同一个 token 所属账号上。

### 13.2 Registry 作为账号状态来源

`MailboxRegistry` 应成为邮箱列表、勾选状态、授权状态、上次错误的唯一来源。前端可以缓存展示，但初始化和勾选变更都应以 registry 为准。

建议 registry 增加这些字段：

```json
{
  "email": "a@gmail.com",
  "provider": "gmail",
  "selected": true,
  "authorized": true,
  "auth_source": "local_tokens",
  "last_auth_checked_at": "2026-06-04T10:00:00+08:00",
  "last_scan_at": "2026-06-04T10:15:00+08:00",
  "last_scan_status": "done",
  "last_error": "",
  "card_count": 5
}
```

`card_count` 可以由聚合 active cards 时回填，也可以仅作为前端展示统计，不作为业务判断依据。

### 13.3 不建议长期保留 `state.mailbox`

文档中说 `state.mailbox` 语义降级，这对兼容现有代码有帮助。但长期看它容易重新变成误操作来源。建议：

- 短期保留：只用于兼容旧函数和 Ask 默认目标
- 新代码禁止依赖：卡片操作、Ask item 操作、Scan Plan 保存都必须显式传 mailbox
- 中期替换为 `defaultAskMailbox` 或 `primaryMailbox`，语义更清楚

### 13.4 Ask 需要独立目标选择器

当前方案让 Ask 默认使用 `selectedMailboxes[0]`，实现成本最低，但用户不一定理解"第一个勾选邮箱"就是 Ask 目标。建议第一版至少在 Ask 输入框附近显示一个邮箱选择器：

- 单邮箱：只显示当前邮箱
- 多邮箱：下拉选择一个邮箱
- 暂不做"Ask all selected mailboxes"，避免结果合并和操作归属复杂化

这样比让用户去 Sources 调整顺序或勾选状态更直观。

### 13.5 聚合卡片需要稳定排序

`get_active_cards(mailbox="all")` 不应只按 `updated_at` 排序。多邮箱混合后，建议排序规则为：

1. pending 优先于 snoozed / resolved
2. priority 高优先
3. 最近邮件时间或卡片更新时间新优先
4. mailbox 作为稳定 tie-breaker

否则某个邮箱刚扫描完会把全部卡片顶到前面，用户可能误以为另一个邮箱的重要邮件消失了。

### 13.6 扫描状态需要按邮箱保存

多邮箱扫描时前端应维护 `scanRunsByMailbox`，不要只复用当前的 `scanStage` / `scanProgress`。推荐结构：

```typescript
scanRunsByMailbox: Record<string, {
  runId?: string;
  status: "queued" | "running" | "done" | "failed";
  stage?: string;
  progress?: Record<string, unknown>;
  error?: string;
}>;
```

这样失败、重试、底部进度和 Sources 状态都能从同一份状态渲染。

### 13.7 失败邮箱提供单独重试

不要让用户只能重新扫描所有勾选邮箱。Sources 抽屉中的失败邮箱应提供 `Retry`，只重新跑该邮箱的 `start_mail_agent_run(mailbox)`。

### 13.8 删除邮箱不删除数据，但要隐藏卡片

`remove_mailbox(mailbox)` 保留历史数据是合理的，但聚合接口需要默认只聚合 registry 中仍存在的邮箱。被移除邮箱的 cards 不应再出现在 `mailbox="all"` 结果里，除非未来提供"恢复已移除邮箱"入口。

### 13.9 用户偏好必须带邮箱维度

当前 `prefs/snooze`、`prefs/learning` 是全局 key。多邮箱后建议改为：

```text
mailbox/{email}/prefs/snooze
mailbox/{email}/prefs/learning
```

否则用户在工作邮箱点了"不要优先这个 sender"，可能影响私人邮箱里的同名 sender 或相似 thread。

### 13.10 防误操作做后端兜底

前端使用 `card.details.mailbox` 还不够，后端也应校验：

- `card_id` 必须存在于传入 mailbox 的 active cards 中
- `message_id` / `thread_id` 必须能在该 mailbox 的缓存或 Gmail 结果中找到
- `reply_now`、`trash_from_ask`、`mark_read_from_ask` 不允许只凭前端传入的邮箱直接操作未知 message

这能防止前端状态错乱时把 A 邮箱的卡片操作打到 B 邮箱。

## 十四、验收标准

### 14.1 本地 dev 邮箱发现

- `gmail_tokens/` 下存在 2 个有效 Gmail token 文件时，Sources 抽屉展示 2 个邮箱。
- 每个邮箱地址来自 Gmail profile API，不来自文件名猜测。
- 无效或过期 token 的邮箱仍可展示，但状态为 `Re-auth needed`，并显示失败原因。
- 首次发现的新邮箱默认 `selected=true`，并写入 `MailboxRegistry`。

### 14.2 Anna 平台授权边界

- 平台只注入 1 个 Gmail token 时，Sources 只展示该 token 对应邮箱。
- 手动添加与当前 token 不匹配的邮箱时，后端拒绝写入 registry，并返回 unauthorized。
- UI 明确说明当前平台多账号限制，不展示虚假的多账号可用状态。

### 14.3 勾选状态持久化

- 取消勾选某邮箱后刷新 app，该邮箱仍保持未勾选。
- 取消勾选某邮箱后，该邮箱卡片立即从 Brief 列表隐藏。
- 重新勾选该邮箱后，已有卡片无需重新扫描即可重新显示。
- 全部取消勾选时，Brief 扫描按钮禁用，并显示空状态。

### 14.4 聚合卡片展示

- `get_active_cards(mailbox="all")` 返回所有 registry 内邮箱的 active cards。
- 前端只展示 `selectedMailboxes` 中邮箱的卡片。
- 多邮箱混合展示时，每张卡片能看到来源邮箱标签。
- 单邮箱展示时可以隐藏邮箱标签，但卡片详情中仍能看到 mailbox。
- 分类筛选 All / Needs reply / Needs review / Cleanup 对混合卡片生效。

### 14.5 多邮箱扫描流程

- 勾选 A、B、C 三个邮箱后点击 Brief，只扫描 A、B、C，不扫描未勾选邮箱。
- 第一个邮箱扫描期间保持现有全屏扫描体验。
- 第一个邮箱完成后，卡片立即展示；后续邮箱扫描进度显示在底部状态栏。
- 某个邮箱扫描失败时，其他邮箱继续扫描。
- 全部完成后展示汇总，包含每个邮箱的成功卡片数或失败原因。
- 失败邮箱可单独重试，不需要重扫所有邮箱。

### 14.6 操作归属安全

- 打开卡片详情、生成草稿、发送回复、标记已读、删除、snooze、restore 都使用 `card.details.mailbox`。
- 当前 `state.mailbox` 与卡片 mailbox 不一致时，操作仍落到卡片所属邮箱。
- 两个邮箱存在相同 `card_id` 时，前端状态互不污染，草稿、展开状态、发送状态都独立。
- 后端在操作卡片前校验 card 是否存在于传入 mailbox 下；不匹配时拒绝操作。

### 14.7 Ask

- Ask 页面明确显示当前目标邮箱。
- 多个邮箱被勾选时，用户可以明确选择 Ask 目标邮箱；第一版不要求支持 Ask all。
- Ask 结果中的每个可操作 item 都包含 `mailbox`。
- Ask 的 Mark read、Trash、Reply 使用 `item.mailbox`，不使用全局 `state.mailbox`。
- Ask 历史重新渲染后，item 的 mailbox 仍保留，操作仍指向正确邮箱。

### 14.8 Scan Plan、历史和偏好

- 每个邮箱有独立 Scan Plan，修改 A 邮箱配置不影响 B 邮箱。
- Run history 每条记录显示 mailbox tag，并可按邮箱筛选。
- `Don't prioritize` 等学习偏好默认只影响当前邮箱。
- A 邮箱保存的 snooze / learning 不影响 B 邮箱扫描结果。

### 14.9 数据存储兼容

- 旧版本只有单 `state.mailbox`、没有 registry 时，升级后能自动创建 registry。
- 旧 active cards 没有 `details.mailbox` 时，要么补齐当前授权邮箱，要么在 UI 中标为 unknown 并禁止危险操作。
- registry 不保存 access token、refresh token、client secret 等敏感信息。
- local 和 APS 两种 storage provider 下 registry、scan_state、active_cards 行为一致。

### 14.10 回归测试

- 单邮箱用户升级后，Brief、Ask、发信、标已读、删除行为保持不变。
- 没有 Gmail 授权时，仍显示原有授权引导，不进入空白页面。
- 现有单邮箱测试通过：`mailAgentClient.test.ts`、`runHelpers.test.ts`、`cardHelpers.test.ts`。
- 后端 storage integration 测试覆盖 registry 读写、聚合 cards、按邮箱隔离 prefs。
