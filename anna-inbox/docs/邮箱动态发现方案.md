# 邮箱动态发现方案

## 现状

邮箱写死在三处：前端 `DEFAULT_MAILBOX`、state 初始化、后端 `SUPPORTED_MAILBOXES` 白名单。

## 目标

App 上线到 Anna 平台后，根据平台注入的 Gmail OAuth token 自动发现当前授权的邮箱，不再写死。

## 平台已具备的能力

- `GMAIL_ACCESS_TOKEN` / `GOOGLE_ACCESS_TOKEN` 环境变量由平台注入
- `mail_adapter.py:256` 已有 `get_authorized_email()`，调用 Gmail `users/me/profile` 获取真实邮箱

## 实施方案

### 步骤 1：新增工具 `get_authorized_mailbox`

**文件**：`main.py`

新增工具定义和 handler。平台模式调用 `get_authorized_email()` 获取真实邮箱；本地 dev 模式扫描 `gmail_tokens/` 目录获取可用的 token 文件名 → 推导邮箱。

```python
# 工具定义
{
    "name": "get_authorized_mailbox",
    "description": "Discover the authenticated Gmail account.",
    "parameters": [],
}
```

返回格式：
```json
{"mailbox": "hr@anna.partners", "source": "platform"}   // 平台
{"mailbox": "hr@anna.partners", "source": "local_tokens"} // 本地
{"mailbox": "", "source": "none"}                          // 无授权
```

### 步骤 2：移除 `SUPPORTED_MAILBOXES` 白名单

**文件**：`main.py`

删除硬编码的字典，`normalize_mailbox` 改为透传。本地 dev 时可接受任意合法邮箱。

### 步骤 3：前端初始化时发现邮箱

**文件**：`app.js`

- `connectRuntime()` 之后调用 `get_authorized_mailbox`
- 成功 → 设置 `state.mailbox`
- 失败或无授权 → 显示授权引导页（已存在）
- 删除 `DEFAULT_MAILBOX` 常量

### 步骤 4：前端清理

- 删除 `DEFAULT_MAILBOX` 常量
- `state.mailbox` 初始值改为 `""`
- 所有引用 `state.mailbox` 的地方保持不变（运行时已赋值）

## 优先级

| 模式 | 优先级 | 来源 |
|------|--------|------|
| 1. 平台注入 | 最高 | `get_authorized_email()` → Gmail API |
| 2. 本地 token 文件 | 次之 | 扫描 `gmail_tokens/` 目录 |
| 3. 无授权 | 兜底 | 显示授权引导页 |

## 改动范围

| 文件 | 改动 |
|------|------|
| `main.py` | 新增 `get_authorized_mailbox` 工具 + handler；删除 `SUPPORTED_MAILBOXES`；简化 `normalize_mailbox` |
| `app.js` | 删除 `DEFAULT_MAILBOX`；初始化增加邮箱发现调用 |

## 风险

- 平台未注入 token 时，fallback 到本地 token 文件，行为不变
- `normalize_mailbox` 去掉白名单后，本地 dev 可传任意邮箱，需确保对应 token 文件存在
