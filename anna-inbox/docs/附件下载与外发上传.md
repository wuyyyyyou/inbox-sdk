# 附件下载与外发上传

## 下载 / 预览（收件）

邮件详情从 Gmail 元数据读取附件列表。前端通过 `prepare_inbox_attachment_access` 请求轻量访问描述，不通过 JSON-RPC 返回附件字节。

### 缓存后的可靠性

- 列表 `has_attachment` 依赖 `fetch_message_summary`（`format=metadata`）。metadata 请求保留完整 `payload` MIME 树，避免单层 `parts` 丢失嵌套附件。
- History 合并不得用更浅的 attachments 覆盖更完整缓存，也不得把已有 `body_cached` 误标为 false。
- `prepare_inbox_attachment_access` / `prepare_attachment_download` 在本地缓存 miss 或 token 无法解析时，回源 `fetch_and_cache_message` 再解析。
- 前端打开详情时采用 stale-while-revalidate：先展示 IndexedDB 缓存，再拉网络线程页补齐附件元数据。

### 访问路径

收件附件（预览 / 下载）按优先级：

1. Host transient upload（`host/uploadFile` negotiate → PUT → confirm）
2. APS Files（`files/upload_begin` → PUT → `upload_complete` → `download_url`）
3. 本地开发：loopback URL

外发 stage 在平台 / APS 模式下走 APS Files 预签名 PUT；本地 dev 保留 loopback。
预签名 URL 不写入草稿或 APS KV。稳定 object path 只作元数据。

### 前端下载约束

- `blob:` URL 可直接触发浏览器下载；其他 URL 必须先 `fetch` 物化为 Blob，HTTP 响应不是成功状态时直接失败，不创建下载链接。
- 物化后的 Blob 通过临时 blob URL 下载，触发点击并移除临时 `<a>` 后延迟释放该 URL，避免浏览器尚未消费下载数据时过早回收。

### Gmail 附件令牌约束

- 解析令牌时必须校验其中的消息 ID 与当前消息归属一致，跨消息令牌直接拒绝。
- Gmail 刷新 `attachmentId` 后，先尝试当前 ID；若 ID 已变化，则按令牌保存的原始 MIME 附件位置回退匹配。
- 回退只读取原始附件列表并严格校验索引；inline / CID 项、无文件名项、越界或非法索引候选均拒绝，不能因过滤后的列表索引偏移而误选其他附件。

### APS Files 对象路径

- APS Files object path 中的附件标识使用附件令牌的 SHA-256 十六进制摘要，长度固定且不包含原始不透明 Gmail token；原始 token 不进入 APS 对象路径。

**注意**：前端默认 `storageProvider=local` 时 KV 走 local-json，但平台附件仍会调用 APS Files
反向 RPC。Executa 必须始终路由 `files/*` / `storage/*` 响应，否则会 60s 挂死。

前端支持图片、PDF 和受限文本预览；其他格式下载。

## 外发上传（回复 / 转发 / Compose）

### 限制

- **合计 25MB**（个人 Gmail 官方限制为整封所有附件合计，非单文件）
- 多附件
- 拦截可执行/脚本类扩展名（对齐 Gmail 安全列表）

### Stage 流程（策略 A：发送时随 MIME 发出）

大文件字节不得进入 JSON-RPC / APS KV：

1. `begin_stage_outgoing_attachment` → 返回 APS `upload_url`、签名请求头与 `storage_key`
2. 前端 `PUT` 文件字节到 APS `upload_url`（进度条）
3. `complete_stage_outgoing_attachment` → 后端调用 `files/upload_complete` 校验持久化
4. 草稿只持久化元数据：`id / filename / mime_type / size / storage_key`
5. 发送时后端通过 `files/download_url` 读取字节，组装 `multipart/mixed`，调用 Gmail `messages.send`
6. 发送成功或删除草稿后通过 `files/delete` 清理对象

### 草稿持久化

| 草稿 | 工具 |
|------|------|
| Compose / Forward | `create_or_update_compose_draft` 的 `attachments` 字段 |
| 详情 Reply | `save_inbox_thread_draft` 的 `attachments` 字段 |

图片上传成功后使用本地 blob URL 或 `prepare_staged_outgoing_attachment_access` 获取 APS 短期缩略图 URL。

### APS Files 验证

在无 Anna Runtime 的本地环境运行以下脚本：

```sh
cd inbox-tool
python src/tests/test_aps_files_integration.py
```

脚本会模拟 APS Files reverse-RPC 与预签名对象存储，验证收件附件上传、外发附件 stage / complete、发送读取、预览、删除和 object path 边界；不需要真实平台凭据。

相关本地自动化验证还包括 `browserDownload`、`test_attachment_download_host_upload` 和
`test_gmail_body_decode`；这些测试不宣称真实平台或真实邮箱验证。
