# 邮箱同步 P0：缓存优先方案

日期：2026-07-24  
状态：**已实现（P0）**；侧栏 Evidence / 正文预热有后续增量  
当前基线：**App `2.2.1` / Tool `2.3.1`**

## 目标

将邮件列表同步与 AI 检索从「每次问答实时搜索 Gmail」切换为「先同步到本地缓存，再由 AI 检索缓存」。

| 概念 | 作用 |
| --- | --- |
| `display_range_days`（7/30/60） | **仅**控制 Inbox 列表展示投影 |
| 180 天 priority metadata | 首次可检索工作集，与列表天数解耦 |
| 无硬顶 backfill | 更早历史后台继续拉 metadata，除非产品增加用户硬顶 |
| `sync_boundary` | AI / UI 共用的索引边界元数据，不得当作用户最终答案原文 |

## 实现入口（代码事实）

| 层级 | 路径 | 职责 |
| --- | --- | --- |
| 同步核心 | `inbox-tool/src/mail_agent/mail_providers/gmail/mailbox_sync.py` | 180d priority、backfill、boundary、Watch 注册、后台 tick |
| 列表 / 增量工具 | `inbox-tool/src/anna_inbox_executa/gmail_tools.py` | `list_inbox_emails`、`list_cached_emails`、`sync_inbox_cache` |

| 前端轮询 | `anna-inbox/src/app/useAppController.ts` | `silentSyncInbox` → `sync_inbox_cache`；`auto_sync_seconds` 默认 15s |

## 首次与后台同步

1. 首次连接或 `clear_cache` 后，**重置** history / priority / backfill 游标（`reset_mailbox_sync_state`），再优先同步最近 **180 天** All-mail 元数据：主题、发件人、收件人、时间、标签、snippet、附件文件名与 MIME 元数据。
2. 查询：`in:anywhere -in:chats newer_than:180d`；单次 invoke 约 **200** 条（`PRIORITY_BATCH_PER_INVOKE`），完成后立即按 `display_range_days` 从缓存投影列表，不等待整箱历史。
3. 180 天 priority 与更早 backfill 均用 Gmail `messages.list` 分页；**`priority_page_token` / `backfill_page_token` 持久化**，进程退出后下次 `list_inbox_emails` / `sync_inbox_cache` 从断点续跑。
4. 更早历史：`before:<180d 边界日>`，默认 **无硬顶**（`configured_sync_range.backfill = unbounded`）；前台 tick 只推进约 40 条，其余由守护线程多 tick 推进（每 tick 约 100 条）。
5. 后台每次只推进有限批次，避免阻塞列表、AI 请求和 Executa 生命周期；page token 保证不丢进度。

## 增量与 Watch

1. 每个邮箱保存 `history_id` / `last_history_id`；`sync_inbox_cache` 调用 Gmail `history.list` 合并新增、删除、标签变化（已读、星标、归档、重要、垃圾箱等）。
2. History 作用于**完整缓存**，不受列表 `display_range_days` 影响。
3. 配置 `ANNA_INBOX_GMAIL_WATCH_TOPIC=projects/.../topics/...` 后 `ensure_gmail_watch` 调用 `users.watch`（**不设 labelIds**，覆盖全邮箱含 Sent/Trash/Spam）；平台收到 Pub/Sub 后应调 `sync_inbox_cache`。
4. 无 topic 时 `watch_status=skipped_no_topic`；前端 **`auto_sync_seconds`**（0 / 15 / 30 / 60 / 120，默认 15）轮询 `sync_inbox_cache` 为兜底。AI 运行、列表加载、详情打开、页面隐藏等期间暂停调度。
5. History 游标缺失/过期：`resync_required` 时**自动重推 180 天 priority 基线**并后台续跑；不清空用户可见缓存除非用户显式清缓存。

## 数据边界（`sync_boundary`）

每个邮箱持久化（`schema_version=2`）并对外暴露：

| 字段 | 含义 |
| --- | --- |
| `earliest_indexed_at` / `latest_indexed_at` | 当前缓存消息时间上下界 |
| `initial_sync_complete` | 180 天 priority metadata 分页是否耗尽 |
| `backfill_complete` | 更早历史是否分页耗尽 |
| `body_sync_complete` / `attachment_sync_complete` | 正文/附件派生内容是否跟完（后台预热进度；P0 默认可为 false） |
| `last_history_id` | History 游标 |
| `configured_sync_range` | `{ initial_days: 180, backfill: "unbounded", body_sync, attachment_parse }` |
| `cache_total` / `priority_days` | 缓存条数与优先窗口天数 |
| `watch_status` / `watch_expiration` / `watch_resource_id` | Watch 状态 |
| `priority_page_token` / `backfill_page_token` | 可续跑分页（状态内，不一定全部进对外 boundary） |

AI 结果携带 `sync_boundary` 作 Evidence 边界；**禁止**把索引诊断文案直接输出给用户。用户明确时间需求**早于** `earliest_indexed_at` 时，侧栏 `query_mail_evidence` 可做一次受限 Gmail 历史检索（最多 20 条并回写缓存）；Gmail 失败时说明无法完成历史检索，**不能**答「没有」。

## AI 检索规则（当前实现）

侧栏主路径（Host Agent Session / 本地兼容）约定：**全邮箱问答只调 `query_mail_evidence` 一次**，不直接自由循环 `search_email` / `read_email`。

1. **`search_email`（Agent 白名单）**：仅扫描本地缓存（`scan_source=cache`），`display_range_days` **不**隐式缩小检索范围；完整已索引集上排序后再截取 evidence（默认 newest，硬上限约 20）。
2. **`query_mail_evidence`**：Sampling 生成 QueryPlan → 确定性缓存查询 → 可选 body 证据；`search_scope=all_indexed_cache`。仅当时间谓词/表述明确早于 `earliest_indexed_at` 时走受限 Gmail 历史（`history_search`，最多 20 并回写）；失败标 `history_search_failed`。
3. 查询「最早一封 / oldest」必须 `order=oldest`，在**完整已索引集**排序后再截取；不得从 newest 前 20 推断最早日期。
4. **`read_email` 的 `bodyFull`**：只返回已缓存 `body_text`；未同步时返回 `body_pending` + 边界事实，**禁止** AI 路径隐式 Gmail 回源。
5. 普通问答不得回源；**唯一**侧栏只读例外是明确超出缓存最早边界的历史时间搜索（见上）。付款/合同等判断须依赖 bodyFull 证据，不得仅凭 snippet 断言「没有」。

相关 system prompt：`local_agent_session.py`、`anna-inbox/src/app/aiAgentSystemPrompt.ts`。

## 与列表缓存策略的关系

- 列表 UI 策略见 [邮件刷新与 All-mail 缓存策略](邮件刷新与All-mail缓存策略.md)：分类标签投影、`list_cached_emails` 分页、扩大时间窗 7→30→60→All。
- 列表触底自动加载更多；「扩大范围」在后台 refresh 时仍可点；同步中文案为 Syncing（见 `HomeView`）。
- 同步工作集固定 180 天 priority + 无硬顶 backfill，**不与** UI days 绑定。
