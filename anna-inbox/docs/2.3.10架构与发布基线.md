# Anna Inbox 2.3.10 架构与发布基线

## 2.3.10 实际改动

- **附件探测与诊断**：APS 稳定对象首次探测使用 3 秒短超时，超时或连接异常可降级到本地缓存/Gmail/上传链路；上传各阶段记录耗时、来源和错误类型，诊断不包含邮箱、邮件 ID、文件名或 URL。
- **本地缓存一致性**：文件缓存模式读取 `index.json` 时增量扫描单封邮件文件，将索引中遗漏的摘要补齐并按内部时间排序，避免同步中断后本地检索误判为完整索引。
- **证据回答与兜底格式**：付款状态模板把扣款失败、余额不足和需处理通知归入待处理项，与已支付 receipt 分开；AI 工具兜底将毫秒时间戳转为日期，并把长预览以带省略号的列表项输出。

- **搜索交互与一致性**：搜索支持状态值、附件值、AND/OR 的渐进补全和错误本地化；搜索请求按序列与邮箱/查询校验，防止快速输入或切换邮箱时旧响应覆盖新结果；刷新和同步后会重新检索当前条件。
- **本地搜索响应边界**：搜索结果按稳定 offset 和实际 JSON-RPC 帧大小逐条装载，避免大结果页超过 Host 响应预算并保证后续分页不跳过命中；历史附件列表、标记和数量字段均可参与 `has:attachment` 检索。
- **收件附件交付**：收件附件优先读取经过大小校验的本地缓存，缓存未命中才访问 Gmail；Cloud Agent 统一通过确定性 APS Files 路径交付，上传失败按可重试错误重新开始上传，响应 URL 字段按脱敏 schema 诊断。

- **附件下载与令牌兼容性**：附件下载改为先物化非 Blob URL，APS Files 路径使用固定长度的附件标识；Gmail 附件令牌在 attachmentId 刷新时按严格校验后的原始附件位置回退匹配。相关自动化测试已更新，但未进行真实邮箱端到端验证。
- **富文本编辑**：编辑器增加无序/有序列表触发、列表回车拆分与空列表退出，并显示当前选中文本颜色状态；相关单元测试已更新，未进行真实邮箱端到端验证。

## 产品基线

2.0 的主界面是三栏工作台：左侧 AI 侧栏，中间 Inbox Workspace，右侧账户栏。点击邮件后，Mail Detail 从工作区右侧展开。

**唯一智能入口**为 Anna AI Sidebar：默认 Host Agent Session；本地可用 `source=sidebar_local` 兼容路径。Brief 产品面下线。整理、发送、删除和标签 mutation 均须明确用户操作确认。

## 当前版本（App 2.2.9 / Tool 2.3.10）

### 2.3.7 变更

- **Gmail Draft 同步暂时下线**：为确保客户当前可稳定使用草稿功能，草稿箱不再读取、创建、更新或删除 Gmail Draft；Compose 草稿仅通过 Anna APS 保存和跨设备恢复。`list_compose_drafts` / `create_or_update_compose_draft(s)` / `delete_compose_draft` 一律只操作 APS 的 `compose-drafts` 数据。Gmail 中已有草稿在临时方案期间不会出现在 Drafts 分类，也不会被修改或删除（详见[草稿 APS 同步说明](Gmail草稿双向同步方案.md)）。
- **草稿目录瘦身与按需读取**：`list_compose_drafts` 返回轻量目录行（不含完整正文，仅 `body_preview`），并按实际 JSON-RPC 外层结构控制在 `COMPOSE_DRAFT_DIRECTORY_RESPONSE_MAX_BYTES` 帧上限内；支持 `offset` 续页。打开单封草稿时后端按需读取详情，异常超大 HTML 通过短期 loopback `body_url` 提供，禁止写入 JSON-RPC 响应。
- **草稿本地镜像与异步持久化**：Compose 草稿目录与邮件详情回复草稿镜像到浏览器 IndexedDB，先显示镜像再后台以 APS 覆盖；草稿未改动时关闭 Compose / 编辑区不触发 APS 写入。删除草稿采用「撤销窗口」：先乐观隐藏，Toast 过期后才执行远端删除，失败自动恢复。
- **AI Ask 历史迁至 APS**：旧版本地 localStorage 的 Ask 历史因无邮箱归属直接清除；Ask 历史改为按邮箱作用域存取（`get_ai_ask_history` / `save_ai_ask_history`，etag 乐观并发），切换邮箱时先冻结并写回当前邮箱会话再加载目标邮箱历史，清理历史只清当前邮箱。
- **Toast 队列**：单条 Toast 升级为有界队列（最多 4 条），每条带独立过期回调 `onExpire`；用于将可撤销操作（如删除草稿）延后提交到后端，Undo 与过期回调不会并发执行。
- **草稿保存可靠性**：`set_compose_draft` 写后读回校验 APS 持久化结果；保存/删除失败时前端保留本地镜像并提示用户手动重试；批量重存需用户确认覆盖已保存草稿。

### 2.3.6 变更

- **AI 草稿落款**：用户明确指定落款时优先使用指定名称，否则使用当前邮箱资料名，并以邮箱本地部分作为兜底；禁止硬编码账户名称。
- **Compose 批量草稿**：新增批量保存工具调用，支持前端一次提交多封草稿、回写 `id` / `etag` 状态，并按收件人、主题和正文去重历史重复草稿。
- **草稿交互**：批量草稿卡片按单封保存状态控制按钮和成功提示，减少重复保存与重复 RPC。

### 2.3.4 变更

- **界面本地化**：支持中英文切换，日期、设置、邮件详情、编辑器、提示和错误信息跟随当前 locale。
- **线程详情增强**：Reply All 复用线程参与者并排除当前邮箱；AI overview 与 quick replies 按 locale 生成并隔离缓存。
- **编辑器与邮件渲染**：支持对齐、引用、删除线、富文本粘贴安全清洗；邮件 HTML 支持响应式表格、长内容换行和受控 CID 内联图片。
- **附件安全校验**：发送前校验文件名、扩展名、单文件大小和总大小，并保留失败提示。
- **功能审查基线**：当前版本的功能支持结论统一记录在[功能审查基线](功能审查基线.md)。
- **reverse RPC 多 invoke 路由**：`executa_sdk.context` 跟踪当前 `invoke_id`（ContextVar + thread-local）；所有 reverse RPC（sampling / credentials / storage / host upload / embeddings / image / agent session）注入 `params.context.invoke_id`。
- **跨线程 re-bind**：worker / connectivity 池 / 后台 AI turn / custom scan / storage sync bridge 在 `run_coroutine_threadsafe` 与池线程上重绑 `invoke_id`，避免并发 invoke 时 Host 返回 `-32602`。
- **invoke_id 解析**：`context.invoke_id` 优先，兼容顶层 `invoke_id`。
- **AI 侧栏消息格式（App）**：剥离行末粘连 `[DONE]`；已选邮件裸主题/多行加粗折叠为单行列表项；system prompt 约束每封邮件单行 Markdown 列表且禁止流结束标记。

### 继承（2.3.2）

- Evidence Gmail 托底（history + cache_gap）；回复草稿两步流；「仅正文」不展示卡片；AI 侧栏滚动/关闭稳定；详情条件跟随；`auto_sync` 默认 5 秒；本地 Agent prompt 压缩；模型不支持图片的可读提示。

### 继承（2.3.1）

- Evidence 字段澄清与确定性 QueryPlan；确认线程引用；草稿主人身份；选择性 APS；本地 JSON salvage；同步边界 toast；Mail Detail 基础滚动稳定；P0 本地评测。

### 列表分页

- 前端固定 `INBOX_FEED_PAGE_SIZE=100`，**不**进入后端同步逻辑。
- 列表触底自动加载；**不展示** Show more 按钮。
- 所有分类共用分页；切换标签时 `localLimit` 重置为 100。
- Inbox 标签角标计数 `> 99` 显示 `99+`；不截断真实列表。
- `ALL_MAIL_CACHE_FETCH_LIMIT=400` 仅 UI 快照 RPC；AI 检索扫全量本地缓存，不受此限。
- 扩大时间窗（7→30→60→All）仍为底部手动按钮。

### 邮箱同步：缓存优先（P0）

- 列表 `display_range_days` 仅控制 Inbox 展示投影，不限制 AI 检索范围。
- 首次连接 / 清缓存后优先同步最近 180 天 All-mail metadata；更早历史后台无硬顶 backfill。
- `sync_inbox_cache` 用 History 增量合并；可选 Gmail Watch 注册；前端轮询兜底（默认 5s）。
- 每个邮箱暴露 `sync_boundary`；禁止把索引诊断原文当作用户答案。

### AI 只读取证：`query_mail_evidence`

- Host / local 侧栏主路径：邮箱范围问答只调一次 `query_mail_evidence`。
- `search_email` / `read_email`：cache-only。
- Gmail 托底（每轮最多一次）：① 时间早于 `earliest_indexed_at`；② 严格零命中且同步缺口。
- `display_range_days` 不得写入 Agent 选型上下文作为检索边界。
- local route 选择 `query_mail_evidence` 时在 route 内同时生成 QueryPlan，避免重复 Sampling。

### 正文 / 附件预处理、侧栏 local、草稿与详情

- 后台 `content_preprocess` / `preprocess_cached_content_batch`（含 `pypdf`）。
- local 调试：`start_ai_turn(source=sidebar_local)` + 与 Host 相同工具白名单。
- 草稿卡片可编辑插入（确认后出卡）；详情跟随最新消息条件滚动；列表短暂丢消息不关抽屉。

### 继承能力

- 邮箱级 workflow state / AI Ask history（乐观并发 etag，APS 存储）。
- 收件附件 Host transient upload → APS Files；reverse-RPC 超时约 20s。
- 联系人头像仅 People API；平台安全 trace。

### 自动判据类型

| 类型 | 用途 | 示例 |
|------|------|------|
| `has_hit_signal` | 命中有信号关键词 | 邮件、找到、结果、扫描 |
| `has_summary` | 总结性内容 | 总结、进展、概述 |
| `has_domain_warning` | 域名警告 | 发件人域名不一致 |
| `has_notification_awareness` | 通知类识别 | 自动、系统通知、无需回复 |
| `has_no_fabricated_amount_draft` | 金额防编造 | 无美元金额或附附件/核对 |
| `has_per_thread_ownership` | 线程责任归属 | 等待对方、我方需要 |
| `has_batch_limit` | 批量上限声明 | 每批最多、上限、共X封 |
| `has_sorted_dates` | 日历时间排序 | 排序、时间、日期 |
| `honest_not_found` | 诚实空结果 | 未找到、没有找到 |
