# Anna Inbox 功能审查基线

## 基线范围

本审查对应当前项目版本：

- App：`2.2.4`
- Tool：`2.3.4`
- 审查依据：当前源代码、manifest、现有测试和 P0 评测记录
- 审查时间：2026-08-03

本文档是当前版本的功能能力基线。后续功能开发、修复和发布审核应根据实际实现和验证结果更新本文档，不应只根据产品计划或工具声明更新结论。

## 判定规则

### 完全支持

代码具备完整用户入口、业务链路和必要的错误处理，且当前版本没有发现会直接否定 CSV 验收要求的明显缺口。仍需通过真实邮箱验收确认模型质量、性能和第三方服务行为。

### 部分支持

主链路已经存在，但存在功能范围限制、入口不完整、数据覆盖边界、错误恢复不足，或者缺少能够证明 CSV 严格验收指标的端到端证据。

### 不支持

当前版本没有完整实现，或已有实现与 CSV 要求的功能定义不同。例如发送前 Undo 不等于已发送邮件撤回。

### 指标证据原则

`auto_sync_seconds=15` 只证明前台同步触发周期为 15 秒，不证明 Gmail 到 App 的端到端延迟不超过 15 秒。当前代码和测试不能证明同步 `100%` 不遗漏、连接持续 `2-3` 小时不断开，或 AI 在所有真实数据上达到 `90%` 准确率。

## 总体结论

当前版本已经具备 Inbox 工作台、Gmail 基础收发、应用草稿、附件访问、基础富文本和 AI 侧栏主链路。按 CSV 的严格 P0 验收标准，整体结论为：**基础工作流可用，复杂验收能力以部分支持为主；定时发送、已发送撤回、完整 Gmail 原生草稿同步、长时间常驻连接和自动 AI 分类当前不支持或证据不足。**

现有 P0 评测记录为 `52/56`，通过率 `92.86%`，记录见 `tests/P0测试结果-20260731-132014.md`。该结果不能替代真实 Gmail、Cloud agent、local agent 和多平台端到端验收。

## 功能结论

| 功能分类 | 功能点 | 结论 | 当前边界 |
| --- | --- | --- | --- |
| AI 能力 | AI 理解、总结、回答、建议、草稿、搜索 | 部分支持 | 统一 AI 侧栏具备主链路，但模型准确率和 5-10 秒响应无法由代码证明 |
| AI 能力 | 邮件总结 button / AI 对话总结 | 部分支持 | 支持当前线程和 Evidence 总结；受缓存边界、正文预处理和模型质量影响 |
| AI 能力 | AI 对话 | 部分支持 | 支持自然语言搜索、总结、草稿和整理建议；状态变更必须用户确认 |
| 双向同步 | App 操作同步到 Gmail | 部分支持 | 删除、星标、已读、归档、重要等 mutation 存在，但没有 5 秒和 100% 一致性证据 |
| 双向同步 | Gmail / 第三方客户端操作同步到 App | 部分支持 | Gmail History 增量同步存在；cursor 失效时有补偿窗口，不能保证不丢变化 |
| 双向同步 | 新邮件自动到达 App | 部分支持 | 默认 15 秒前台轮询；实际端到端延迟和 100% 不遗漏无法证明 |
| 连接稳定性 | Cloud / local agent 长时间连接 | 不支持 | 有 heartbeat 和断线重连，但没有 2-3 小时常驻连接和任务保活证据 |
| 邮件收发 | 新建邮件立即发送 | 完全支持 | Compose、正文、收件人、附件和 Gmail 发送链路存在，发送前有 10 秒 Undo 窗口 |
| 邮件收发 | 定时发送 | 不支持 | 未发现真正的 Gmail 定时发送或后台定时任务链路 |
| 邮件收发 | Reply | 完全支持 | 支持线程关联、原主题、回复头和发送 |
| 邮件收发 | Reply All | 部分支持 | 线程详情和编辑器菜单均提供入口；前端按最新邮件推断发件人、原 To/Cc，去除当前邮箱并按大小写无关去重后通过 Gmail 发送。已具备单元测试，但尚无真实 Gmail 多参与者端到端验收 |
| 邮件收发 | Forward、Cc、Bcc | 完全支持 | 支持转发正文、HTML、To、Cc、Bcc 和附件 |
| 邮件收发 | 发送状态 | 部分支持 | 有 10 秒待发送倒计时、发送中、成功、失败提示；失败的线程回复会恢复为可编辑草稿，但没有跨重启的持久化发送任务状态 |
| 邮件收发 | 发送失败重试 | 部分支持 | Compose 失败草稿保留，线程回复失败会恢复可编辑草稿，用户可再次发送；没有专用 Retry、自动退避和幂等发送队列 |
| 邮件收发 | 撤回已发送邮件 | 不支持 | Gmail API 只能移动发件箱副本或删除本地副本，不能撤回已经投递到收件人邮箱的邮件；当前只有发送前 10 秒 Undo |
| 草稿箱 | 自动保存、手动保存、退出保存、恢复、覆盖、删除 | 完全支持 | Anna 应用管理的草稿生命周期基本完整，使用 etag 处理并发 |
| 草稿箱 | Gmail 原生 Drafts 跨设备双向同步 | 部分支持 | 主要是 Anna application-managed draft，未发现完整 Gmail Draft API 双向同步 |
| 附件 | 上传 | 部分支持 | 支持多格式、多文件、进度、单文件与总量 25 MB 限制、文件名安全校验和发送前校验；异常清理和真实邮箱端到端证据不足 |
| 附件 | 下载 | 部分支持 | 支持短期 URL、APS Files、loopback 和浏览器下载；过期或失败需手动重试 |
| 附件 | 预览 | 部分支持 | PDF、图片、文本、音频、视频支持预览；Office、日历和压缩包提供明确的下载降级，未引入不安全的在线转换服务 |
| 邮件渲染 | HTML、图片、表格、长邮件 | 部分支持 | DOMPurify + sandbox iframe、响应式表格滚动、长 URL/代码换行、清洗空内容提示和受控 CID 映射已支持；复杂外部资源、超长内容性能和真实邮件兼容性仍需验收 |
| 其他邮箱 | Sent、Drafts、Archive、Trash、Spam、All mail 查看 | 完全支持 | Gmail 系统分类和前端列表投影存在 |
| 其他邮箱 | 其他箱操作 | 部分支持 | Gmail 系统分类基本可用，Todo、Snoozed、Done 主要依赖前端本地 flags |
| 富文本编辑 | 粗体、斜体、下划线、字号、颜色、列表、链接 | 部分支持 | 支持基础格式、删除线、引用、四方向对齐、链接编辑、富文本粘贴和安全清洗；不承诺表格、图片、字体等复杂邮件编辑能力 |
| 富文本编辑 | 撤销、重做、快捷键 | 部分支持 | 有工具栏、撤销/重做、Ctrl/Cmd 快捷键、焦点提示和键盘可关闭链接弹层；依赖 `document.execCommand`，跨 WebView 一致性证据不足 |
| 邮件搜索 | 标题、正文、发件人、收件人、关键词 | 部分支持 | 支持字段搜索，但主要作用于当前缓存，正文未缓存时会漏检 |
| 邮件搜索 | 组合条件 | 部分支持 | 支持 AND、OR、否定；不支持括号和真正的引号短语 |
| 邮件搜索 | 模糊搜索 | 部分支持 | 支持大小写不敏感子串匹配，不支持纠错、相关性排序和完整 Gmail 语义 |
| 邮件搜索 | 无结果提示 | 部分支持 | 合法查询有空状态；非法查询可能被当成不过滤 |
| Todo 管理 | 创建、完成、批量操作、同步 | 部分支持 | 用户可操作 Todo/Done，但缺少统一后端模型、完整批量闭环和跨设备一致性证据 |
| AI 总结 | 长邮件、多语言、长度、重点、失败提示、附件 | 部分支持 | 工具和提示路径存在，但真实内容质量、附件解析和所有边界场景无法证明 |
| AI Draft | 单封回复、批量生成、批量上下文回复、风格改写 | 部分支持 | 支持单封和批量，但批量实际硬上限为 5 封，模型质量和跨 thread 隔离需真实验收 |
| AI 分类 | 自动分类、准确率、修改、重新分类、新邮件自动分类 | 部分支持 | 有“需回复/可清理”整理建议；没有完整持久化 AI 分类、自动 Gmail Label 或新邮件自动分类闭环 |
| AI 搜索 | 标题、发件人、收件人、关键词、正文 | 部分支持 | 支持 `query_mail_evidence` 和本地搜索，但受已索引缓存、边界和结果上限限制 |

## 后续更新规则

每次涉及以下能力的代码变更或发布审核，都应更新本文档对应行和“当前版本”信息：

- Gmail 同步、History、Watch、轮询、断线恢复和超时
- Compose、Reply、Reply All、Forward、发送、定时发送和撤回
- 草稿保存、恢复、删除、跨设备同步和 Gmail 原生 Drafts
- 附件上传、下载、预览和发送
- HTML 渲染、富文本编辑和搜索解析
- Todo、邮箱分类和状态 mutation
- AI 搜索、总结、Draft、分类、批量上限和评测结果

更新结论时必须同时说明：

- 是代码能力变化，还是仅新增测试证据
- 是否增加或消除功能边界
- 是否有对应单元测试、脚本测试或真实邮箱端到端验证
- 5 秒、100%、准确率和长连接等指标是否已有可复现测量

如果某项从“部分支持”升级为“完全支持”，必须补充可复现的验证命令、测试结果或真实环境验收记录，不能只依据 UI 入口或 manifest 描述升级。
